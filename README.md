# AI Test Data Filler

Chrome extension (Manifest V3). One click fills the forms on the current tab with fictional test data written by
the user's own **Claude** or **ChatGPT** API key. Random names, surnames, emails, addresses and text differ on every click.
Works on any http(s) page. Never submits a form.

## Try it locally

1. Open `chrome://extensions`, turn on **Developer mode**, click **Load unpacked**, select this folder.
2. The setup page opens. Paste a Claude or OpenAI key, pick which AI to use, press **Test connection**.
3. Open any page with a form, click the extension icon, press **Fill this page**.

## How it works

`popup` -> `background.js` injects `content.js` into the current tab (via `activeTab`, only after the user clicks)
-> content script lists fillable fields (label, name, type, placeholder, maxlength, min/max, pattern, options)
-> `providers.js` sends that list to the selected provider only -> the reply (field id -> value) goes back to the
content script, which validates it (email format, number range, maxlength, pattern, valid option) and types it in
using the native value setter plus `input`/`change` events so React/Vue forms notice.

**Large-data test:** the second button fills long input. A text field that states its limit (the
`maxlength` attribute, a counter such as `0 / 500`, or nearby text such as "max 500 characters" / "līdz 200 simboliem")
gets real AI-written text fitted to exactly that length: cut at a word boundary, or extended by repeating the text when
the AI wrote less (it is asked for at most ~1500 characters, so longer limits repeat). From 40 characters up the text
ends with ` END`, so a form that cuts input shows no END after saving. Emails, URLs, phones, numbers and dates that
state a limit or `max` are built locally to the exact limit. Fields that state no limit (a name, say) get normal AI
data, not a long text. It replaces values already in text fields. Hints are read only from the field's own label,
placeholder, `aria-describedby` and its own wrapper (never a wrapper holding several fields).

Skipped on purpose: password, file, hidden, disabled, read-only fields, payment card and security-code fields,
and fields that already have a value (unless "overwrite" is ticked).

## Provider rules

- Keys for both providers can be saved; one is selected. Only the selected provider is contacted.
- With one key saved, that provider is used automatically.
- Models are editable (defaults: `claude-haiku-4-5-20251001`, `gpt-4o-mini`). Change them if your account uses others.

## Known limits

- Only plain inputs, textareas, selects, checkboxes and radios. Custom widgets (date pickers built from divs,
  searchable dropdowns, phone-number libraries) are not filled.
- Main frame only, no iframes. Max 80 fields per run.
- Generated IBANs/IDs are fictional and may fail checksum validation.
- Not tested yet: I could not run Chrome from the build environment. Load it unpacked and try a few forms first.

## Publishing to the Chrome Web Store

1. Create a developer account (one-time registration fee) at the Chrome Web Store dashboard.
2. Zip the **contents** of this folder (manifest.json at the zip root). Leave out README.md and PRIVACY.md if you like.
3. Listing needs: description, at least one 1280x800 screenshot, a 128px icon (included), a privacy policy URL
   (host `PRIVACY.md` somewhere public, e.g. a GitHub Pages page or your site).
4. Privacy form: the extension handles **website content** (form field descriptions) and an **API key** (authentication
   information). Both are sent only to the AI provider the user chose, solely to provide the feature. No analytics, no
   selling, no remote code.
5. Justify the permissions:
   - `activeTab` + `scripting`: read and fill the form on the tab the user clicked on, nothing else.
   - `storage`: keep the API key and preferences locally.
   - host permissions `api.anthropic.com`, `api.openai.com`: send the request to the AI provider the user chose.
6. Single purpose statement: "Fill web forms with fictional test data generated by the user's own AI account."

Expect review questions about the broad `scripting` + AI combination. Keeping field values and page text out of the
request, as it does now, is what makes the privacy answers simple. Do not add analytics later without updating the policy.
